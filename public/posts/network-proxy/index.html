比改 hosts 更省心：dev-sidecar 让 GitHub 真正“直连”

用 GitHub 最烦的，不是一直打不开，而是时好时坏。网页转圈，头像裂图，clone 半天没动静——这种“薛定谔的通”，很多时候真不是墙的问题，而是本地 DNS 解析出来的 IP，在当前线路上走不通。

改 hosts 当然能救急，我也用过。但它的问题很明显：IP 会失效，失效了要手动换，换完还得清 DNS 缓存。说到底，hosts 就是手动钉一个 IP，钉对了算运气，钉错了再来一遍。

最近我在用 dev-sidecar，思路和 hosts 不是一回事，记一下。

它的逻辑

dev-sidecar 可以理解成一个本地代理。名字里的 sidecar 来自 service-mesh，就是给开发者打辅助的“边车”。

  • 在本机起一个代理服务
  • 系统代理指向它
  • 拦截 github.com 这些域名的 HTTPS 请求
  • 靠 DNS 优选和 SNI 修改，把请求代理到国内加速通道，或者直连 GitHub 官方 IP

你不用自己改 IP，它会选。

检测机制

这块我觉得做得比较实在。

启动后它会先做 DNS 优选，把域名下能用的 IP 解析出来，测速，然后挑最快的。GitHub 直连加速则是改 SNI 字段，思路参考了 FastGithub。

请求拦截也不止一条路。它可以配多个镜像站做备份，带测速；访问失败或超时，就自动切到备用站点。一条路不通，它会换另一条。

怎么用

下载安装

去官方仓库的 Releases 页面下。Windows 选文件带 2.3.0-windows-x86_64.exe的那个文件 安装时 Windows 可能弹“未知发行者”，选保留就行。

安装根证书

第一次打开，界面会提示装根证书。这一步得做，不然 HTTPS 加速不生效。

证书是本地随机生成的，不收集用户信息，安全性不用太担心。安装时注意两点：选“本地计算机”，存储位置选“受信任的根证书颁发机构”。如果提示拒绝访问，关掉软件，用管理员身份重开再试。

保持运行

装完让 dev-sidecar 在后台跑着就行。建议设置里打开开机自启，省得每次手动开。

退出还原

程序退出时，不管是正常关闭，还是点“退出并还原”，系统代理都会恢复到运行前的状态。

一个需要留意的细节

有个小坑：Electron 监听不到 Windows 的关机事件，所以开着 dev-sidecar 直接重启，重启后可能暂时上不了网。手动启动一下 dev-sidecar 就能恢复。这个问题在 1.8.9 之后已经修了。

和其他工具冲突吗

会。dev-sidecar 启动时会自动改系统代理，所以和其他代理软件冲突。如果你已经有别的代理工具在跑，建议别同时用。

另外，它和 Watt Toolkit（原 Steam++）一起用时，需要把 Watt Toolkit 切到 hosts 模式启动。不过这个应用主要就是直连访问 GitHub；如果你已经有稳定的代理方案，官方也建议不用再装。

除了 GitHub 还能加速什么

默认还覆盖 Stack Overflow、Google 学术、npm、PyPI、Docker 等开发者常用资源。装一个，日常开发里的网络问题能少操心不少。

平台支持

Windows、macOS、Linux 都有安装包。

Windows 是 exe，macOS 是 dmg，Linux 有 deb 和 rpm。macOS 安装时可能要去“系统偏好设置 → 安全性与隐私 → 通用”里解锁并允许。

和改 hosts 方案怎么选

两者不冲突，但建议二选一。

  • 改 hosts：手动固定一个 IP，失效了手动换，适合愿意定期折腾的人
  • dev-sidecar：自动测、自动换、自动兜底，适合配一次就不想再管的人

本质上都在解决同一个问题：找一个能用的 IP。区别只是手动还是自动。

写在最后

dev-sidecar 是开源项目，仓库在 docmirror/dev-sidecar。用之前建议去仓库页面看一眼，了解清楚它能做什么、不做什么。

觉得好用的话，去点个 Star。
